Frequently Asked Questions

Everything you need to know about OSIVault architecture and deployment.

How does OSIVault compare to standard database column encryption?

Standard database column encryption uses a single database key that can be compromised if the database server is breached. OSIVault uses field-level AES-256-GCM envelope encryption with per-row Data Encryption Keys (DEKs) and AWS KMS integration. Even if a raw database dump is stolen, the data is unreadable.

How does the YubiKey WebAuthn hardware key protection work?

The OSIVault Desktop Admin Panel uses FIDO2 / CTAP2 WebAuthn protocols. During login, a cryptographic challenge nonce is issued to your YubiKey hardware device. Only touching the physical gold metal sensor signs the assertion with Ed25519, preventing remote credential theft.

Can I query encrypted fields without decrypting the entire database?

Yes! OSIVault generates HMAC-SHA256 blind search hashes for indexed encrypted fields. You can perform exact-match SQL queries (`WHERE ssn_hash = 'search_hash_8a9...'`) directly in PostgreSQL without exposing plaintext data in memory.
